## 一、Tavern 双向同步

**技术路径已验证可行：**

```
SillyTavern Extension (浏览器 JS)
    ↕ HTTP fetch
OC Workbench API (localhost:3000/api/tavern/*)
    ↕
Workbench 数据库（角色、时间线、记忆）
```

SillyTavern 扩展系统可用钩子：
- `context.chat` 可读写聊天记录
- `MESSAGE_RECEIVED` 事件：每条消息后触发
- `CHARACTER_EDITED` 事件：监听角色卡变化
- `generateQuietPrompt()`：后台静默调用 AI 提取记忆
- `writeExtensionField()`：把 Workbench 数据写回角色卡

**同步方向优先级：**

| 方向 | 难度 | 价值 | 优先级 |
|---|---|---|---|
| Workbench → Tavern（注入上下文） | 低 | 高 | P0 |
| Tavern → Workbench（提取记忆） | 中 | 高 | P1 |
| 实时双向（每条消息同步） | 高 | 中 | 暂缓 |

## 二、角色动态状态（核心数据结构）

竞品（Piney、Nibbli）只管静态设定，无人做动态状态。

**建议的状态快照结构：**

```
角色状态快照
├── 时间戳（对应时间线位置）
├── 情绪状态
├── 体力/精力
├── 持有物品
├── 当前所在地点
├── 未完成的承诺/任务
└── 与其他角色的当前关系值
```

这个结构是整个产品的核心数据资产，Tavern 注入、时间线回溯、多角色共现都依赖它。

## 三、具体功能列表

### MVP 阶段

- **角色卡导入**：支持读取 SillyTavern PNG/JSON 格式，把现有角色卡设定导入 Workbench，降低迁移成本
- **时间�� → 世界书导出**：把共享时间线事件转成 Tavern 世界书 JSON 格式，用户手动导入 Tavern
- **角色状态卡**：在 Workbench 里记录角色动态状态（情绪、持有物、未完成承诺），竞品空白

### 插件联通后（中期）

- **半自动记忆提取**：对话结束后，插件调用 `generateQuietPrompt()` 让 AI 总结关键事件，生成候选记忆列表，用户确认后写入 Workbench 时间线
- **上下文注入**：开始对话前，插件从 Workbench 拉取当前角色状态和近期事件，自动注入为临时世界书条目
- **多角色场景同步**：共现页面对应 Tavern 群组聊天，同步多个角色状态

### 长期差异化

- **叙事分支管理（AU 管理）**：同一角色在不同平行宇宙里的状态分开管理，互不干扰。竞品无此功能。
